# 评估中心使用与实现说明

## 使用顺序

1. 在「实验管理」新增或编辑用例，选择知识库、填写问题，并选择必需证据。可选证据、禁止命中的证据和预期角色用于进一步检查。
2. 填写参考答案或逐行评分要点；按问题选择回答需要的图、公式、说明、表格。
3. 选择执行策略。不选时使用用例所属知识库的默认策略；不是执行所有策略。开启「模型答案评审」会增加模型调用，未标注答案的题目不会伪造评分。
4. 开始评估后逐题执行。失败不会中断其他题目；停止在当前题完成后生效。离开页面不会自动启动后续题，回来可在实验记录中继续。失败和未完成题可创建重试实验，保留原实验和已成功题目的结果。
5. 查看逐题复盘中的实际回答、图片、公式、预期证据、重排结果、缺失项、禁止命中和评审理由。需要核验原文时可从引用证据查看文档信息。
6. 在同一评估条件下换策略再运行，或选择一个完整实验作为基准。JSON 报告包含完整快照和明细；CSV 包含逐题结果并处理逗号、引号、换行及表格公式前缀。

## 证据标注

- 优先在界面选择知识单元，保存为 `id:知识单元ID`。标题更改不影响命中。
- 文档锚点：`anchor:文档ID#fig:4` 或 `anchor:文档ID#eq:1`，限定文档后匹配，避免不同文档相同图号误命中。
- 显式关键词：`keyword:per-symbol`，在检索结果的标题和内容中匹配。它不等价于语义正确性。
- 兼容旧版完整标题，也可写 `title:完整标题`。界面会提醒其容易受改名影响。旧测试集中的 `Fig. 4`、`DOI` 等不会自动猜测成关键词，建议编辑为稳定 ID 或明确的关键词标注。

## 指标口径（evidence-v2）

- Recall@10：去重后的重排前十条结果命中的必需证据数 / 去重后的必需证据总数。
- Precision@10：前十条中相关结果数 / 10；返回不足十条的空位仍计入分母。相关结果包含必需和可选证据。
- MRR@10：前十条中首个相关结果排名的倒数，未命中为 0。
- 角色覆盖率：重排检索结果覆盖的预期角色数 / 预期角色总数。未标注角色时为空，不复用完整性模型的自评分。
- 禁止命中：检查重排结果以及后续扩展、补检后的实际上下文。
- 检索通过：Recall@10 ≥ 0.8 且没有禁止命中，不代表答案正确。
- 答案正确性、依据支持度、完整性：模型依据参考答案、要点和实际引用证据给出 0～1 分及理由，需要人工复核。未启用、无标注、无效输出或模型不可用时保留为空，不用“有引用”代替评分。
- 图片与公式：检查正文图片占位符是否关联到引用、受控图片文件是否可读取、是否存在公式排版标记及必需内容；外部图片地址不主动抓取，显示未验证。数学正确性、图片像素内容和图文语义关系仍需结合答案评审人工核对。
- 聚合只平均成功执行且具有对应标注的题目。失败题、未执行题、未评分题不补 0；页面同时显示总题数、成功数、失败数和评分数量。空实验拒绝运行。

## 策略与快照

评估执行会实际使用指定策略的 knowledge_type、按问题意图配置的检索角色，以及 completeness_policy 的阈值和低覆盖处理方式。评估不会重新抽取文档，也不会修改知识库默认策略。逐题详情保存实际执行计划。

每轮保存用例快照、策略配置、模型名称、提示词全文、检索规划、知识库内容摘要与评分版本。知识库摘要覆盖知识单元、文档索引与关系；不包含外部向量索引文件和图片二进制快照。它用于识别版本差异，不是可恢复整个知识库的备份。

每题执行前检测模型、提示词、知识库内容或检索规划是否发生变化，变化时保存为执行错误并提示重新创建实验。策略本身使用开始时的快照。仅全题执行成功且评估条件相同的实验参与自动策略对比；趋势还要求策略配置一致。旧版实验保留但不混入新版指标。

## 接口与兼容

- `POST /api/evaluation/run`：JSON 请求 `{dataset_name, strategy_id?, judge_answers?, baseline_id?}`，创建待执行实验并立即返回。替代旧版长请求 query 参数接口。
- `POST /api/evaluation/runs/{id}/step`：`{case_id}`，执行一题并保存。SQL 状态与修订号防止重复并发认领；重复提交已完成题不会重跑。
- `GET /api/evaluation/runs/{id}`：读取进度；中断的执行超过保护窗口后标记为错误，允许重试。
- `POST /api/evaluation/runs/{id}/cancel`：停止后续题。
- `POST /api/evaluation/runs/{id}/retry`：创建重试实验，成功结果保留，错误或未完成题重新排队。
- `/golden` 支持新增、列表，`/golden/{id}` 支持编辑、删除。实验快照不随用例编辑或删除而改变。
- `GET /overview` 支持 dataset_name、strategy_name 和 run_id；按所选历史实验计算同条件趋势及基准对比。

启动后端时自动为 golden_case 新增 evaluation_config，为 evaluation_run 新增 status、owner_id、revision、config。升级不删除旧数据，可重复执行。需要重启后端让新路由与数据库兼容升级生效，前端使用重新构建的产物。

## 验证

`backend/tests/test_evaluation.py` 覆盖指标、稳定证据标注、问题分类、真实零分、策略生效、失败隔离、幂等、取消、重试、快照漂移、历史与基准比较、访问控制、数据库兼容升级。

`frontend/scripts/check-evaluation.cjs` 使用本地模拟接口验证页面交互，包含未评估状态、逐题运行、失败重试、回答与图片预览、用例编辑、策略结果以及桌面和手机布局。截图位于 artifacts/frontend/evaluation-*.png，截图分数是测试数据，不代表真实知识库效果。
