# 芯片设计知识图谱

## 使用方式

进入「知识图谱」，选择一个知识库或全部可用知识库。

- 左侧大纲按「芯片设计 → 架构 → IP 架构 / 模块架构」展开。模块分类覆盖截图中的发射端线性化、发射端输出、均衡与反馈、接收判决链、数据路径与速率变换、时钟与相位、求和与输出，并补充跨时钟域与复位、电源与偏置。
- 中间为可展开、收起、聚焦的思维导图；可以滚动浏览。搜索支持中文名称和技术缩写，按 Enter 定位。
- 点击模块查看当前已收录的候选技术；勾选 2–4 项打开对比表。
- 对比表保留原理、指标、约束和文档对比摘录，可以点击打开来源。缺失信息显示「暂无明确依据」。
- 来源面板展示已保存原文片段或知识点摘录、图片；PDF 文档使用原 PDF 阅读器定位页码。
- 导出大纲生成 Markdown 文件，不是原生 `.xmind` 文件。

## 数据与归类

`GET /api/graph/design-map?kb_id=...` 从当前可访问的知识库读取知识单元，建立实时、只读的设计视图。无需再次抽取文档，也不会改写原来的文章章节目录。

分类规则位于 `backend/app/domain/design_map.py` 的 `MODULES` / `FACETS`：

1. 功能模块以名称、概念与内容中的模块术语关联支持材料。
2. 技术候选必须在知识点标题或概念中明确出现。只在正文中顺带提及的术语不会被单独列为实现方案。
3. 同名技术跨文档归并，来源知识点不去重丢弃；分类汇总使用唯一知识点及文档 ID，避免交叉归类重复计数。
4. 具体模拟 / 数字 FFE 有明确名称时，不将该条资料重复归入通用 FFE。
5. 其他具名解决方案可以保留为模块下的候选节点；未能归类的资料进入「待归类知识」。
6. 概念、性能指标、设计约束和方案对比还提供独立导航分支。
7. 仅使用检索可用生命周期，排除已废弃、草稿和占位单元。AI 抽取资料保留待核对标记。

这是一套规则归类与文档证据浏览功能，不是电路替换可行性判定器。相同模块的技术可能互补或属于不同实现层级；不会把共同出现、提及或相同分类自动声明为可直接替换。数值与条件展示知识摘录，不跨文档推算、不把整篇论文指标自动归给其中每个电路模块。新术语可扩充 `MODULES`，再刷新页面生效。

接口执行知识库范围过滤；普通用户、知识专家及算法工程师均可从导航进入，账号切换时重新加载授权范围。已有 `/graph` 关系接口保留兼容。

## 验证

后端测试：

```powershell
.venv/Scripts/python.exe -m pytest backend/tests/test_design_map.py backend/tests/test_design_map_api.py backend/tests/test_catalog_sync.py -q -p no:cacheprovider
```

构建及类型检查在 frontend 目录运行 `npm run build` 与 `npx vue-tsc --noEmit`。

浏览器测试使用隔离服务和本地数据快照，不写入真实知识库。先生成固定测试数据，或通过 `--database data/akrag.db` 以只读方式生成现有数据快照：

```powershell
$env:PYTHONPATH='backend'
.venv/Scripts/python.exe backend/tests/export_design_map_fixture.py
# 安装有 Playwright 的环境中运行；必要时将 PLAYWRIGHT_MODULE 指向现有 Playwright 包。
node frontend/scripts/check-design-map.cjs
```

浏览器覆盖模块选择、技术对比、来源弹窗、搜索、无结果状态、大纲下载、错误恢复和 1280 / 768 / 390 像素布局。效果图输出到 `artifacts/frontend/design-map-*.png`。
