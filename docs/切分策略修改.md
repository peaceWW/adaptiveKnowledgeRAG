当前**真正生效的切分策略不是向导里那三个单选**，而是：先解析结构，再按「是不是学术论文 + 知识类型」走两条抽取路径。

```text
上传 PDF/MD
    → parser / academic_parse     先切页、章节、图/公式清单（还不是知识单元）
    → classifier                  标 knowledge_type、academic_paper
    → Technical/Incident/API Strategy.build_units()
         ├─ 学术论文  → extract_paper_units()     清单节点 + 章节语义单元
         └─ 其它文档  → extract_units_from_text() 空行/句子切块 + 关键词猜角色
```

界面上的「语义知识单元 / 按章节 / 固定 Token」只写入 `process_config`，抽取代码不读，所以改选项不会换策略。

---

### 实际两条策略

**1. 普通文档：段落启发式切块**

按空行拆段（短于 40 字丢掉），拆不出再用句子凑到约 180 字。每块一条 Knowledge Unit，用关键词猜 `semantic_role`。故障案例、API 文档也走这条。

**2. 学术论文：结构清单 + 章节语义（不是固定 token）**

- 解析器先识别 IEEE 章节、公式、图 caption、表、`[n]`
- 每章一条 `kind=section`，每个 Fig/Eq/Table/Ref 各一条独立 unit
- 有模型时按章调用 LLM 再抽 principle/metric 等；没有模型则对该章再 `_split_blocks` 取前几段
