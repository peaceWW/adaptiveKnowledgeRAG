# 专业知识文档提取与召回落地方案

> 基准文档：`docs/A_10_Gb_s_Hybrid_ADC-Based_Receiver_With_Embedded_Analog_and_Per-Symbol_Dynamically_Enabled_Digital_Equalization.pdf`  
> 设计输入：`docs/专业知识文档方案设计.md`、`docs/架构方案.md`  
> 原则：**不另起一套知识模型，在现有 Knowledge Unit / 四层存储 / Adaptive Retrieval 上补齐论文图文公式引用链路。**

---

## 1. 要解决什么

对 IEEE JSSC 这类双栏专业 PDF，传统「PDF → 纯文本 → 固定 token 切块 → 向量库」会同时丢掉：

- 图与解释它的正文（Fig.4 架构图 vs Section II 的 hybrid receiver 叙述）
- 公式的符号语义（Eq.(1) 的 α₋₁ 与 `(·)₂`）
- 表格对比指标（TABLE I prior work）
- 正文 citation 到参考文献条目（`[12]` → Tabasy 10 GS/s TI-SAR）
- 页码 / 章节 / DOI 级引用

目标不是「答得通」，而是：

> 检索最小 Knowledge Node，回答时回溯 Parent Section，并把关联 Figure / Equation / Table / Citation 一并取出。

对应产品问题示例：

> 为什么这种 ADC 可以降低数字均衡器功耗？

期望召回 **principle（动态 bypass）+ Fig.4 + threshold detector 叙述 + 功耗 metric**，而不是只命中 Abstract 里的一句 summary。

## 2. 需求摘要（从设计文档收敛）

| 需求 | 落地含义 |
| --- | --- |
| 不以 Chunk 为核心，以 Knowledge Node 为核心 | 继续用 `KnowledgeUnit`，用 `unit_meta.kind` 区分 equation / figure / table / citation / section |
| 图不能只做 OCR | Caption + 裁剪原图 + Vision 语义描述 + 与正文关系 |
| 公式不能只转文本 | 截图 + LaTeX + 自然语言解释 + 上下文 + 关联图 |
| 引用可追溯 | Document / Section / Page / Fig / Eq / DOI 全部进 citation |
| References 建引用图 | `[n]` 独立 unit，正文 `REFERENCES` 到该 unit |
| 四层存储 | SQL 元数据、Qdrant 向量、MinIO 资产、SQL/Neo4j 关系 |
| 父子结构 | Section 为 parent，段落/图/公式为 child；检索叶子、回答带 parent |
| 混合检索 | 角色过滤改为加权，图/公式作为扩展召回，而不是被 filter 掉 |

不在本方案范围：另起 MinerU/Docling/Neo4j 作为 P0 依赖。现有 PyMuPDF + Postgres/SQLite + Qdrant + MinIO + `KnowledgeRelation` 足够先把召回做对。版面工具只作为 **PDF 抽不出字时的降级**。

### 3.2 会直接打低召回的缺口

| 缺口 | 现象 | 对这篇论文的后果 |
| --- | --- | --- |
| 图只有 caption，`_maybe_vision_figure` 恒返回空 | 图 unit 几乎不可检索 | 问「hybrid ADC architecture」很难命中 Fig.4 |
| 图未裁剪、未进 MinIO | 回答无法出示原图 | 无法做到「相关图：Fig.4 + 图片」 |
| 公式常无 LaTeX、无截图、无变量表 | `formula` 向量是乱码 raw | 问「α₋₁ 怎么算」对不上 Eq.(1) |
| `KnowledgeUnit.parent_id` 从未写入 | 有字段无父子树 | 命中 Eq.(1) 时拿不到 Section III.A 原文 |
| Qdrant **按 required_roles 硬过滤** | figure 被标成 `interface`，formula 不在 cause 计划里 | 「为什么能省功耗」只搜 principle，Fig.4 / Eq / metric 全部被滤掉 |
| ingest 关系只进 SQL，检索不读 | `EXPLAINED_BY` / `REFERENCES` 闲置 | 命中段落不会带出 Fig.9、`[12]` |
| Neo4j 只写 `RELATED_TO` concept | 图扩展对论文几乎无效 | 问 FFE 扩不出 Fig.9 |
| 向量只 embed `title+content` | 缺 caption / latex / vision 描述分通道 | 图描述和公式 LaTeX 权重过低 |
| IEEE Xplore 流可能抽不出正文 | `test_academic_paper.py` 已注明 Flate 失败 | 15 页 PDF 变成空 sections，后续全空 |
| 回答 citation 只有 chapter/page | 无 fig/eq/doi/image | 不像企业专业知识库 |
| Chat UI 纯文本 | `ChatView.vue` 引用列表无图 | 即然后端带了图用户也看不到 |

结论：**抽取清单已经有了，召回失败主要发生在「角色硬过滤 + 关系不用 + 图/公式没有可检索文本 + 没有 parent 回溯」。**

## 4. 以这篇论文为基准的知识模型

不新增表。一个 Knowledge Node = 一条 `knowledge_unit`。

### 4.1 节点种类 `unit_meta.kind`

| kind | semantic_role 建议 | 这篇论文实例 | 最小必填 |
| --- | --- | --- | --- |
| `metadata` | summary | 标题 / 作者 / JSSC 2016 / DOI 10.1109/JSSC.2015.2504555 | title, doi, venue, year |
| `section` | background / principle / metric / summary | I Introduction；II Architecture；III.A SAR+FFE | section_id, page, text |
| `equation` | formula | Eq.(1) precursor/postcursor tap | eq_id, page, raw, latex?, bbox, image_key |
| `figure` | interface（检索不靠这个 role） | Fig.4 hybrid RX；Fig.9 unit SAR；Fig.10 32-way TI-ADC | fig_id, caption, page, image_key, description |
| `table` | metric / comparison | TABLE I prior ADC-based RX | table_id, caption, rows |
| `citation` | reference | `[12]` Tabasy TI-SAR with embedded FFE/DFE | cite_key, text, cited_in_sections |
| `concept` | principle / parameter / constraint | Reliable symbol detection；per-symbol dynamic enabling | 由 LLM 从 section 抽，必须带 source_span |

`semantic_role` 继续表示**知识角色**（原理/指标/公式），`kind` 表示**载体**（图/公式/表）。二者不要混成一个枚举。

### 4.2 父子树（写入 `parent_id`）

```text
Document: Shafik 2016 Hybrid ADC RX
│
├── [section] Abstract
├── [section] I. Introduction
├── [section] II. Architecture
│     ├── [concept] Reliable Symbol Detection
│     ├── [figure] Fig.2 / Fig.3
│     ├── [concept] Hybrid ADC Receiver
│     ├── [figure] Fig.4  Proposed hybrid architecture
│     └── [figure] Fig.5
├── [section] III.A  SAR ADC With Embedded 3-Tap FFE
│     ├── [equation] Eq.(1)  α₋₁ / α₁
│     ├── [figure] Fig.9  unit SAR + FFE
│     └── [figure] Fig.10 32-way 10 GS/s TI-ADC
├── [section] Measurement Results   → [table] TABLE I, [metric] 36.4 dB / 38 mW / 28 mW
└── [section] References
      ├── [citation] [1] Harwood 12.5 Gb/s
      ├── [citation] [12] Tabasy 6-bit 10 GS/s
      └── ...
```

规则：

- Section unit 的 `parent_id = None`（或指向 document 级 metadata unit）
- 同章节的 figure / equation / table / concept 的 `parent_id = 该 section unit.id`
- 检索命中叶子后，**强制把 parent section 放进回答上下文**（即使它没进 Top-K）

### 4.3 关系类型（扩展 `RelationType`，P0 只落 SQL）

| 关系 | from → to | 这篇论文 |
| --- | --- | --- |
| `BELONGS_TO` | 叶子 → section | Eq.(1) → III.A |
| `ILLUSTRATES` | figure → concept/section | Fig.4 → Hybrid ADC Receiver |
| `EXPLAINED_BY` | equation → 解释段落 | Eq.(1) → nearby paragraph |
| `HAS_FIGURE` / `HAS_EQUATION` / `HAS_TABLE` | section → 资产 | III.B → Fig.10 |
| `REFERENCES` | 正文 unit → citation unit | Architecture 段 → `[12]` |
| `RELATED_TO` | unit → catalog concept | Fig.10 → ADC / TI-ADC / SAR |

正文里出现 `Fig. 4`、`Fig.4`、`(1)`、`[12]` 时，用正则建边，不依赖 LLM。LLM 只允许**补充** `ILLUSTRATES`，不得覆盖清单边。

### 4.4 单节点存储形态（沿用现有列 + `unit_meta`）

```json
{
  "title": "Fig. 4",
  "content": "Fig. 4. Proposed hybrid ADC-based receiver architecture.\nDescription: ADC embeds 3-tap analog FFE; threshold detector gates digital EQ.",
  "semantic_role": "interface",
  "parent_id": "<section-II-unit-id>",
  "source_chapter": "II",
  "source_section": "Architecture",
  "source_page": 3,
  "source_span": "Fig. 4. Proposed hybrid ADC-based receiver architecture.",
  "concepts": ["ADC", "FFE", "hybrid receiver"],
  "unit_meta": {
    "kind": "figure",
    "anchor": "fig:4",
    "fig_id": "4",
    "caption": "Proposed hybrid ADC-based receiver architecture",
    "image_key": "docs/{doc_id}/fig/4.png",
    "bbox": [x0, y0, x1, y1],
    "figure_type": "architecture_diagram",
    "components": ["CTLE", "TI-ADC", "threshold detector", "digital EQ"],
    "parameters": {"data_rate": "10 Gb/s"},
    "embed_text": "hybrid ADC receiver architecture 3-tap analog FFE per-symbol digital equalizer bypass"
  }
}
```

公式节点额外字段：`eq_id`、`latex`、`raw`、`variables`、`image_key`。  
引用节点额外字段：`cite_key`、`cited_in_sections`、`title/authors/year/doi`（能解析则填）。

## 5. 提取策略（入库 Pipeline）

保持现有 LangGraph：`parse → classify → extract → index`。在节点内部加深，不改主图。

```text
PDF bytes
  │
  ├─① Layout parse（academic_parse，已有）
  │    双栏阅读顺序 / 章节 / caption / 公式块 / 表 / [n]
  │    失败则 ①b OCR 降级（P1）
  ├─② Asset materialize（新增）
  │    按 bbox 裁 Fig / Eq → PNG → MinIO
  ├─③ Inventory units（paper_extractor，已有）
  │    每个 eq/fig/table/cite 一条 unit，coverage 卡死
  ├─④ Vision enrich（补齐空函数）
  │    公式 → LaTeX+符号；图 → 类型/组件/参数/描述
  ├─⑤ Section LLM units（已有 prompt）
  │    禁止再抽公式全文和参考文献条目
  ├─⑥ Relation builder（增强）
  │    正则 Fig./Eq./[n] + parent_id + LLM ILLUSTRATES
  └─⑦ Coverage + Review
       缺清单或 vision 失败 → stub + 人工审核
```

### 5.1 解析层：先保证「这篇 PDF 抽得出字」

`academic_parse.parse_pdf_document` 已覆盖双栏。对这篇 15 页 IEEE Xplore PDF 还要补：

1. **文本为空时的降级**（测试已承认部分副本 Flate 失败）  
   - 先 `page.get_text("rawdict")` / `get_text("blocks")`  
   - 仍空则整页 rasterize（150–200 dpi）+ 现有 Vision 或 Tesseract  
   - `structure.parse_quality = {pages_ok, pages_ocr, text_len}`  
   - `pages_ok < 80%` 时文档进入审核，禁止静默空抽
2. **图 bbox**：不要只扫 caption 行。对每个 `Fig. N` caption block，向上取最近的 image/drawing block 作为图区域；caption 在双栏底部、图在另一栏时，用「同页 y 最近 + 同栏优先」。
3. **公式 bbox**：已有 Math 字体启发。Vision 前必须有 bbox，否则跳过 LaTeX，保留 raw + nearby_text，confidence ≤ 0.55。
4. **跨页 caption**：`Fig. 10. ...` 被栏断开时，合并连续行直到句号。
5. **参考文献跨行**：`collect_citations` 已拼接续行；补作者/年/venue 的轻量解析即可，不必上 Crossref（P1）。

P0 **不上** MinerU。只有 OCR 率仍低、或版面混乱时再加可选后端，输出必须映射到现有 `structure` schema，避免第二套字段。

### 5.2 资产层：图和公式必须变成对象

新增 `ingestion/assets.py`（建议）：

```text
put_pdf_asset(minio, doc_id, kind, anchor, png_bytes)
  → docs/{document_id}/fig/4.png
  → docs/{document_id}/eq/1.png
```

- 复用已有 `render_region_png`  
- figure 无 bbox 时退化为 **caption 所在页半页截图**，`unit_meta.crop_mode=page_fallback`，进审核  
- `Document.object_key` 继续存原 PDF；图/公式是派生对象，不替换原件

### 5.3 抽取层：清单优先，LLM 补语义

继续 `extract_paper_units` 顺序：

1. metadata + index terms  
2. inventory（eq / fig / table / cite）  
3. 按 section 调 `technical-extractor.yaml`  
4. 无 LLM 时 heuristic 段落  
5. `apply_coverage_stubs`

改造点：

| 项 | 现状 | 改为 |
| --- | --- | --- |
| `_maybe_vision_figure` | `return ""` | 调 Vision，产出 description / figure_type / components / parameters |
| `_figure_unit.content` | caption | caption + Description + 关键参数，作为 embed 文本 |
| `_equation_unit` | 有 bbox 才 LaTeX | 同时存 PNG；Vision 再要 `meaning`、`variables` |
| section LLM | 不抽公式/参考文献 | 额外要求 `relations: [{type, to_key}]`，`to_key` 只能是已有 `fig:` / `eq:` / `cite:` |
| parent | 未写 | extract 结束后按 `source_chapter` 把叶子 `parent_id` 指到 section unit |

Vision prompt 必须约束：**只描述图上可见结构，禁止用训练知识补电路。** 参数只能来自 caption 或同页正文。

### 5.4 覆盖率：从「有没有这条」升级到「能不能检索」

现有 `check_ingest_coverage` 只查 anchor 是否存在。对论文再加 **检索就绪** 条件：

| 对象 | 清单完整 | 检索就绪 |
| --- | --- | --- |
| figure | 有 fig_id + caption | 有 image_key 且 description ≥ 40 字 |
| equation | 有 eq_id + raw | 有 latex 或 image_key |
| table | 有 table_id | 有 rows 或 caption 含数字 |
| citation | 有 `[n]` | 有非空 text |
| section | 有 Abstract + References | text_len 达标 |

`complete` 仍用于是否自动发布；`retrieval_ready_score` 写入 `document.classification.coverage`，工作台可展示。Fig 无描述不阻塞入库，但必须进 Review。

### 5.5 这篇 PDF 的抽取验收清单

入库后至少应出现：

- 15 页、`genre=academic_paper`、DOI、Index Terms（ADC-based receiver, FFE, DFE, SAR…）
- Abstract / Introduction / Architecture / Circuit / Measurement / Conclusion / References
- Fig.4、Fig.9、Fig.10、Fig.11 及 caption
- Eq.(1)（FFE tap）及 nearby 中的 binary-to-decimal 说明
- TABLE I 对比表
- `[1]` `[3]` `[12]` 等引用，且 Introduction/Architecture 有 `cited_in_sections`
- 关系：Fig.4 `ILLUSTRATES` Architecture；Eq.(1) `EXPLAINED_BY` III.A；正文 `[12]` `REFERENCES` citation unit

## 6. 存储策略（四层如何分工，不扩栈）

| 层 | 现有组件 | 存什么 | 不存什么 |
| --- | --- | --- | --- |
| SQL | `knowledge_unit` / `knowledge_relation` / `document` | 节点、父子、关系、页码、unit_meta、coverage | 向量、原图二进制 |
| Vector | Qdrant / 内存 | **可检索文本** 的 embedding + 过滤字段 | 当数据库用 |
| Object | MinIO / 本地 | 原 PDF、Fig PNG、Eq PNG | 元数据副本 |
| Graph | Neo4j 可选；P0 用 SQL | P1 再同步 unit–unit 边 | 不作为召回唯一路径 |

### 6.1 一条 unit 写几条向量（提高召回的关键）

现在：`embed(title + content)` 一条。论文节点改为 **主向量 + 可选辅向量**，payload 用同一 `unit_id`，靠 `payload.channel` 区分：

| channel | 文本 | 用途 |
| --- | --- | --- |
| `primary` | title + content（含 caption/description/latex） | 默认语义检索 |
| `symbol` | 仅对 formula：`α-1 alpha_{-1} precursor tap FFE` | 符号/别名召回 |
| `caption` | 仅对 figure/table：caption + 组件名 | 「Fig.4 架构」这类问法 |

P0 可以先把 symbol/caption **拼进 primary content**（改动最小）。P1 再真正多向量。禁止把整页原文再切 1000 token 当第四路，否则会冲掉 unit 语义。

### 6.2 Qdrant payload 增补（`workflow.index_units` + review 重索引）

```text
kb_id, knowledge_type, semantic_role, domain, lifecycle, source_level
kind, anchor, document_id, parent_id, source_page, source_chapter
fig_id / eq_id / cite_key（有则写）
concepts, title, content[:2000]
```

过滤要用 `kind`、`document_id`、`parent_id`，不能只用 `semantic_role`。

### 6.3 角色硬过滤必须改掉（当前最大召回 bug）

`QdrantStore.search(..., roles=required_roles)` 是 `must`。  
`cause_analysis` 的 required_roles = definition / root_cause / principle / symptom，于是：

- Fig.4（interface）被丢
- Eq.(1)（formula）被丢
- TABLE I（metric）被丢
- `[12]`（reference）被丢

**P0 改法：**

1. 向量检索 **不再 must roles**；roles 只用于 RRF 加权（命中 required_role ×1.2，其余 ×1.0）  
2. 关键字检索同样取消强制 role；或 role 作为 should  
3. Planner 增加 `expand_kinds: ["figure","equation","table"]`，学术论文默认打开  
4. Completeness 仍按 required_roles 检查，缺的走二次检索，二次检索也允许带 expand_kinds

### 6.4 关系存储 P0 走 SQL

ingest 已写 `KnowledgeRelation`。补齐：

- `to_kind=unit` 必须解析到真实 id（现在 anchor 未解析时会落到 `to_kind=anchor`，检索无法 join）  
- 新增关系枚举后，`index_units` 同步 `neo4j_store.upsert_relation`（有 Neo4j 才写）  
- 检索侧新增 `_expand_neighbors(unit_ids)`：查 SQL `from_id/to_id in hits`，把 figure/equation/citation/parent 追加进 hits，**不经过 role 过滤**

Neo4j 从「按 concept 名 expand」升级为「按 unit id 扩 1 跳」放到 P1。没有 Neo4j 时召回不得退化。

## 7. 检索策略（针对召回率）

在现有 `understand → plan → retrieve → complete → answer` 上加 **学术论文扩展通道**，不新开工作流。

```text
Query
  │
  ├ understand  补 comparison intent；topics 增加 ADC/FFE/SAR/Fig.N/Eq.N
  ├ plan        required_roles 作完整性清单，不再当检索白名单
  ├ retrieve
  │    A 向量（无 role must）
  │    B 关键字 / 文档索引（Fig.4、α-1、10 GS/s 靠这个）
  │    C SQL 关系 1 跳 + parent_id 回溯
  │    D RRF 融合（A/B 权重 1.0，C 权重 0.8）
  │    E Rerank 前把 parent section 拼进文档（上下文 Enrich，不另占一路召回名额）
  ├ complete    缺 metric/formula/figure 时 secondary 按 kind 补召
  └ answer      结构化 citation：page + section + fig/eq + doi + image_key
```

### 7.1 Query Understanding 增量

`TOPIC_PATTERNS` 与芯片 CDC 关键词并列，加入：

```text
ADC|SAR|FFE|DFE|CTLE|CDR|ENOB|SNDR|BER|TI-ADC
Fig\.?\s*\d+|Eq\.?\s*\(\d+\)|α-?1|alpha
功耗|均衡|time-interleaved|per-symbol
```

Intent：现有枚举加上已有 `comparison` 的解析（`_parse_intent` 目前会把 comparison 丢掉，一律变 definition）。问「和先前 ADC RX 比怎样」必须走到 comparison，才能要求 metric。

问「Fig.4 是什么」：topics 含 `Fig.4`，retrieve 先按 `unit_meta.fig_id=4` **精确查 SQL**，再向量。这是最高性价比的召回补丁。

### 7.2 Hierarchical retrieval 具体规则

对每个 fused hit：

1. 若 `parent_id` 存在且 parent 不在 hits：append parent（标记 `via=parent`，不参与 rerank 竞争，只进 LLM 上下文）  
2. 查 `HAS_FIGURE/HAS_EQUATION/ILLUSTRATES/EXPLAINED_BY/REFERENCES` 一跳，最多每类 3 个  
3. 上下文组装顺序：parent section → 命中 unit → 关联图/公式（附 `image_key`）→ citation 短文

这样问功耗时：命中「threshold detector bypass digital EQ」段落 → 带上 Section II → 带上 Fig.4 → 带上 38 mW / 28 mW metric。

### 7.3 Completeness 针对论文问题类型

| 问题类型 | 必有 kind/role | 二次检索 |
| --- | --- | --- |
| 架构 / 为什么 | principle + 至少 1 个 figure | 按 document_id + kind=figure |
| 公式怎么算 | formula + parent section | 按 eq_id 或 latex 符号 |
| 性能对比 | metric + table | kind=table |
| 方案出处 | reference | kind=citation，沿 REFERENCES |
| 参数（10 GS/s、6-bit） | parameter/metric | 关键字精确 |

现有 completeness 只看 role 集合，会在「召回了 principle 但没图」时仍判 100%。论文策略要加 `missing_kinds`。

### 7.4 Embedding 文本规范（不换模型也能涨召回）

| kind | 写入 embed 的 content 模板 |
| --- | --- |
| figure | `Fig.{id}. {caption}\nType: ...\nComponents: ...\nDescription: ...` |
| equation | `Equation ({id})\n$$\n{latex}\n$$\nMeaning: ...\nSymbols: alpha_-1=precursor ...\nContext: ...` |
| table | 表头 + 前 40 行已有；补一列自然语言：「this work 10 Gb/s 40 nm ...」 |
| citation | `[12] {raw}\nCited in: III.A\nTopic: embedded FFE in SAR ADC` |
| section | 保持原文块，不要摘要替代原文 |

## 8. 回答与引用（产品侧）

后端 `answer` 的 citation 从 `{title, role, chapter, page}` 扩为：

```json
{
  "knowledge_id": "...",
  "title": "Fig. 4",
  "role": "interface",
  "kind": "figure",
  "chapter": "II",
  "section": "Architecture",
  "page": 3,
  "anchor": "fig:4",
  "image_key": "docs/.../fig/4.png",
  "doi": "10.1109/JSSC.2015.2504555",
  "document_title": "A 10 Gb/s Hybrid ADC-Based Receiver ..."
}
```

生成约束（改 `answer-generator.yaml`）：

- 只依据 hits，禁止用参数记忆补 10 GS/s / 6-bit  
- 若 hits 含 figure，正文必须出现「相关图：Fig.N — caption」  
- 若含 formula，写出 LaTeX 并点名 Eq.(N) / 页码  
- 文末来源：作者、期刊、页码、章节、DOI  

前端 P0：`ChatView` 引用 Tab 显示 kind、页码、锚点；有 `image_key` 则请求 `/api/documents/{id}/assets/{key}` 展示图片。P1 再做回答区插图。

审核 P0：`ReviewView` 对 `kind=figure/equation` 显示原图/公式截图 + caption/latex，便于专家改 description。

## 12. 风险与刻意不做的事

1. **不要为论文新建 `paper_chunk` 表。** 会和 Knowledge Unit 双轨，检索更差。  
2. **不要用 role 白名单当向量过滤器。** 这是当前召回的第一杀手。  
3. **不要用 OCR 文本代替 Vision 描述。** OCR 给检索词，Vision 给结构知识，content 里两者并存。  
4. **不要在 P0 引入第二套 PDF 解析器当主路径。** 先把 PyMuPDF schema 填满；解析器可插拔，字段不可分叉。  
5. **不要让 LLM 抽参考文献和编号公式。** 清单器更稳，LLM 只做章节语义和 ILLUSTRATES。  
6. **Vision 失败必须降级为 caption/raw，而不是丢弃节点。** coverage stub 已有这个思想，图/公式要沿用。
