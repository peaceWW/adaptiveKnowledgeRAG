# 知识单元原 PDF 展示

## 改动

知识审核页中间默认显示上传时保存的 PDF 原始页面，由现有 PyMuPDF 渲染整页；不再用抽取文本重排“原文”。双栏、字体、图片、公式、图注与页内位置来自原文件。

- 左栏知识单元列表、中栏原稿阅读器、右栏抽取结果与审核表单各自滚动。
- PDF 页码与知识点序号分别展示，切换知识点按 `source_page` 定位来源页。
- 支持翻页、输入页码、适合宽度、125%/150%/200% 缩放、大图阅读、Esc 退出和原 PDF 下载。
- “提取文本（辅助）”保留来源页文字，方便复制与对照；整页渲染图本身不提供文字选择或重新编辑。
- 无有效来源页时明确提示，允许手动翻页；本次不推测页内高亮位置。
- 快速切换知识点时忽略过期响应；页面请求可取消，最近 6 张渲染图在组件内缓存并在退出时释放。
- 新上传文件使用独立对象路径，避免同名上传覆盖其他文档所引用的原稿。

## 接口

- `GET /api/documents/{id}/source`：原 PDF 页数与页面尺寸。
- `GET /api/documents/{id}/pages/{page}?width=2000`：整页 PNG，页码从 1 开始；限制输出像素量。
- `GET /api/documents/{id}/original`：下载保存的 PDF 原文件。

客户端沿用项目 API 会话请求，服务端从文档记录的对象存储路径读取原稿。PDF 缺失、损坏、加密、越界与存储不可用均给出明确错误，不回退为冒充原稿的重排文本。

## 验证

- 后端 5 项测试：整页图像像素与直接渲染一致（含公式、矢量图和嵌入图片）、缺失/非法/加密文件及越界页码、旋转页、API 与下载、压缩页面流损坏。
- 前端构建及 Vue/TypeScript 类型检查。
- 浏览器回归：来源页联动、独立翻页、定位知识点、缩放、大图阅读、辅助文本、快速切换、缺失原稿与重试；覆盖 1920/1280/768/390px。
- 浏览器验证使用专门构造的测试论文与接口数据，截图不代表用户论文。测试页面图片由生产接口使用的同一渲染函数生成。

## 已知边界与启用

更新后需要让后端加载新增接口，并让前端加载最新代码。已入库文档只要对象存储中仍保留完整原 PDF，即可直接使用，无需重新抽取知识点。

本地 `docs/A_10_Gb_s_Hybrid_ADC-Based_Receiver_With_Embedded_Analog_and_Per-Symbol_Dynamically_Enabled_Digital_Equalization.pdf` 副本在 PyMuPDF 与 Poppler 中均报告压缩数据错误，测试的第 1/3 页在 PyMuPDF 中为空白。因此本次没有把该副本作为成功显示的验证证据，也没有修改该原文件；实际已上传副本是否正常需要通过运行中的存储服务核对。

项目的原文与截图会写入 `data/storage/`（可用 `STORAGE_DIR` 覆盖）。MinIO 不可用时也落盘，重启后端后仍可读取。若历史原文件是在旧版内存回退中丢失的，需要重新上传完整原文件。
