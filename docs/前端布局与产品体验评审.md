# 前端布局与产品体验评审

## 本次结论

主要问题是内容宽度与窗口脱节，以及上传、抽取、启用、审核之间缺少清晰的状态反馈。现有导航已经覆盖知识生产与消费的主要环节，应优先让这些环节连通，而不是继续增加一级菜单。

## 已落地

| 问题 | 调整 |
| --- | --- |
| 多个业务页面限制为 1280/1440px，大屏右侧空置 | 在应用布局层统一释放页面宽度，内容区可收缩；文档工作区按主列表与分析侧栏分配宽度 |
| 标题与六步流程挤在同一行 | 拆成页面标题、统计、流程导航、业务工作区四个层级 |
| 文档管理只有上传入口 | 增加统计、名称搜索、状态筛选、每页 10 条、刷新、知识点数量与启用状态 |
| 选中文档与分析结果对应不清 | 分析侧栏展示完整文件名，列表支持键盘 Enter 选择 |
| 状态与下一步动作脱节 | 待选策略显示推荐/手动选择；抽取成功后提供启用；已启用文档提供审核入口 |
| 抽取失败仍显示完成 | 检查返回状态，失败展示原因，完成页使用真实知识点数与启用状态 |
| 多文件上传时忙碌状态提前结束 | 用待处理文件数量跟踪上传，处理期间锁定知识库切换 |
| 空知识库无法继续 | 提供创建知识库入口，未选择知识库时禁止上传 |
| 不支持的文件格式被宣称支持 | 根据当前解析器限制为 PDF、MD、TXT、HTML；校验格式、空文件和 200MB 上限 |
| 配置控件修改后不生效 | 禁用尚未接入后台的自定义切分、上下文和审核开关，并解释当前规则；保留实际生效的自动启用 |
| 搜索框宣称全局搜索，但目标页不读取查询 | 明确搜索范围为知识库名称/领域/描述，并在知识库页面应用与同步查询 |
| 知识库无法直接进入所属文档 | 卡片增加管理文档入口，传递并校验知识库 ID |
| 创建知识库缺少校验与提交反馈 | 校验名称、领域、策略，添加提交状态与成功反馈 |
| 通知红点无真实通知数据 | 移除无功能的通知红点，保留问答入口 |
| 请求失败缺少可见反馈 | 统一接口错误提示，并在短时间内合并提示 |

领域展示来自知识库配置，并非独立模型识别结果，因此相应修改了字段名称。

## 后续产品优先级

### P1：文档处理可靠性

- 增加持久化后台任务、失败阶段、重试与取消接口；目前上传和抽取仍等待同步请求，不应在前端伪造可恢复任务。
- 增加文件内容去重、文档版本与替换流程，明确重复上传对知识单元的影响。
- 接入真实 DOCX/PPTX 解析后再开放对应格式。
- 将处理配置真正传入切分与抽取流程，并为实际生效的参数提供验证。

### P1：权限与发布边界

- 当前用户切换和菜单可见性由前端会话控制；正式产品需要身份认证、路由访问约束及后端统一鉴权，不能把隐藏菜单当权限保护。
- 统一“已抽取、已启用、已审核、可检索”的产品定义，后续将可检索知识点数量与审核进度展示给知识维护者。

### P2：其他功能区

- 工作台：把待审核、失败任务等指标和角色可执行的任务入口对应起来。
- 问答与检索：继续强化来源定位、无结果解释与答案反馈闭环。
- 模型中心：当前主要是提示词编辑/测试界面，建议名称与功能一致，并补充保存状态、版本比较和回滚。
- 系统管理：当前主要是健康、用户及 ACL 的只读表格，后续权限管理需与后端授权能力一起实现。

## 验证范围

- 生产构建及 Vue/TypeScript 类型检查。
- 使用隔离模拟接口的浏览器回归：大屏内容宽度、分页条数、搜索、状态筛选、错误说明、抽取失败不进入完成页、知识库搜索及所属文档跳转。
- 检查 1920px 桌面、1280px、768px、390px 视口；窄屏允许步骤条内部滚动，页面无横向溢出。
- 截图位于 `artifacts/frontend/`；回归脚本位于 `frontend/scripts/check-ui.cjs`，通过 `PLAYWRIGHT_MODULE` 指定现有 Playwright 安装路径。
- 本次浏览器验证使用模拟数据，未验证真实模型服务、文档解析耗时与后端存储链路。
